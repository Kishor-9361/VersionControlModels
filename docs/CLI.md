# VCM CLI Reference Guide

Comprehensive command-line interface documentation for **VCM (Version Control Models)**.

---

## Command Overview

```
Usage: vcm [OPTIONS] COMMAND [ARGS]...

  VCM (Version Control Models) - Model DNA Version Control Platform.

Options:
  --version  Show the version and exit.
  --help     Show this message and exit.

Commands:
  init             Initialize VCM in current project.
  train            Wrap model training and automatically capture code, data, metrics, and environment.
  models           List and filter tracked models.
  info             Show detailed model metadata.
  compare          Compare two models side-by-side.
  lineage          Show complete lineage tree for a model.
  export           Export model metadata to JSON file or stdout.
  repair           Rebuild SQLite database from existing .vcm.json files on disk.
  session          Manage development and training sessions.
  timeline         Display model evolution timeline and progression tracking.
  timeline-reason  Add or view reasoning for why a model version was created.
  analysis         Analyze model lineages, code evolutions, and recommendations.
  reproduce        Rebuild and reproduce a trained model from its metadata.
  deploy           Deploy a model and log its audit trail.
  audit            Inspect model deployment audit trail for an environment.
  config           Manage VCM configuration settings.
  version          Show VCM version.
```

## Core Model Versioning Commands

### `vcm init`
Initializes VCM configuration and local SQLite database in the current project directory.

```bash
vcm init [OPTIONS]
```

**Options:**
- `--db-path TEXT`: Custom path for SQLite database index (default: `.vcm/vcm.db`).
- `--models-dir TEXT`: Default directory where trained model binaries are stored (default: `models`).
- `--remote TEXT`: Optional remote repository URL.

**Example:**
```bash
vcm init
# Output:
# [SUCCESS] VCM initialized successfully in /path/to/project
# Created .vcm/ directory, local SQLite database, and default models/ directory.
```

---

### `vcm train`
Executes an arbitrary Python training script, measures execution duration, and automatically extracts Model DNA (Git commit SHA, branch, DVC dataset hashes, hyperparameters, environment dependencies, and evaluation metrics).

```bash
vcm train [OPTIONS]
```

**Options:**
- `--model-name TEXT`: **[Required]** Human-readable name or identifier for the model.
- `--script TEXT`: **[Required]** Path to the Python training script.
- `--dataset TEXT`: Path to training dataset file or folder.
- `--metrics TEXT`: Path to metrics JSON file generated by the training script.
- `--params TEXT`: Hyperparameter key=value pair (can be passed multiple times or space-separated).
- `--model-file TEXT`: Path to generated model artifact file (default: `models/<model_name>.pkl`).
- `--output-dir TEXT`: Directory to store the model artifact.
- `--reasoning TEXT`: Developer rationale explaining why this model version was trained.

**Examples:**
```bash
# Basic training run
vcm train --model-name iris_v1 \
          --script train.py \
          --dataset data/iris.csv \
          --metrics metrics.json \
          --params lr=0.01 max_depth=3

# Training run with developer reasoning
vcm train --model-name iris_rf_v2 \
          --script train.py \
          --dataset data/iris_v2.csv \
          --metrics metrics.json \
          --params n_estimators=100 max_depth=5 \
          --reasoning "Switched to Random Forest ensemble to reduce overfitting on feature set B"
```

### `vcm models`
Lists and filters tracked models stored in the local SQLite catalog.

```bash
vcm models [OPTIONS]
```

**Options:**
- `--dataset TEXT`: Filter models trained on a specific dataset path or DVC content hash.
- `--best`: Filter to show only the top-performing model (based on `--sort-by`).
- `--limit INTEGER`: Maximum number of records to display (default: all).
- `--sort-by TEXT`: Metric key to sort records by (default: `accuracy`).
- `--format [table|json|csv]`: Output presentation format (default: `table`).
- `--export TEXT`: Destination file path to save output as JSON or CSV.

**Examples:**
```bash
# View top 5 models sorted by accuracy
vcm models --limit 5 --sort-by accuracy

# Get the single best model trained on a specific dataset
vcm models --dataset data/train.csv --best

# Export all model records to a CSV report
vcm models --format csv --export ./reports/all_models.csv
```

---

### `vcm info`
Displays the complete Model DNA record for a specified model.

```bash
vcm info [OPTIONS] MODEL_REF
```

**Arguments:**
- `MODEL_REF`: Model identifier (name, file path, or hash).

**Options:**
- `--json`: Print raw formatted JSON instead of the formatted terminal view.

**Example:**
```bash
vcm info iris_rf_v2
vcm info models/iris_rf_v2.pkl --json
```

---

### `vcm compare`
Performs an automated side-by-side comparative diff of two models across their evaluation metrics, hyperparameters, dataset hashes, Git commits, and runtime environments.

```bash
vcm compare MODEL1_REF MODEL2_REF
```

**Example:**
```bash
vcm compare iris_v1 iris_rf_v2
# Output:
# ==============================================================================
# VCM MODEL COMPARISON: iris_v1 vs iris_rf_v2
# ==============================================================================
# Metric               iris_v1        iris_rf_v2     Delta          Direction

# 
# Hyperparameters:
#   lr:                0.01           (removed)

#   max_depth:         3              5              +2
# 
# Git Commits:

# ==============================================================================
```

### `vcm lineage`
Renders a visual tree connecting the model to its training environment, dataset revisions, Git commits, and predecessor models.

```bash
vcm lineage MODEL_REF
```

**Example:**
```bash
vcm lineage iris_rf_v2
```

---

### `vcm export`
Exports full metadata for a model to an external JSON file or stdout.

```bash
vcm export [OPTIONS] MODEL_REF
```

**Options:**
- `--output TEXT`: File path to write exported JSON (prints to stdout if omitted).

---

### `vcm repair`
Self-healing utility that scans the project workspace for all `<model>.vcm.json` sidecar files and completely rebuilds the SQLite database index from scratch.

```bash
vcm repair
```

## Session Tracking Commands (`vcm session`)

Session tracking groups iterative training runs into cohesive development blocks with automatic terminal logging, secret masking, and comparative analytics.

### `vcm session start`
Starts a new development session and begins intercepting standard terminal streams.

```bash
vcm session start [SESSION_NAME]
```

**Example:**
```bash
vcm session start "feature_engineering_exp"
```

---

### `vcm session end`
Concludes the currently active session, computes session duration, summarizes models trained, writes the terminal log, and registers the session in the database.

```bash
vcm session end
```

---

### `vcm session list`
Lists all recorded sessions.

```bash
vcm session list [OPTIONS]
```

**Options:**
- `--status [active|completed|all]`: Filter by session status.
- `--format [table|json]`: Output format.

---

### `vcm session info`
Displays detailed information for a specific session, including models trained, duration, git commits, and annotations.

```bash
vcm session info SESSION_REF
```

---

### `vcm session annotate`
Attaches a timestamped developer note or observation to the currently active session.

```bash
vcm session annotate [OPTIONS] "TEXT"
```

**Options:**
- `--model TEXT`: Associate this annotation with a specific model name.

**Example:**
```bash
vcm session annotate "Noticed overfitting when max_depth exceeds 8"
vcm session annotate "Validation loss converged" --model iris_rf_v2
```

---

### `vcm session logs`
Displays the captured terminal activity log for a session with sensitive API keys and secrets masked out.

```bash
vcm session logs [OPTIONS] SESSION_NAME
```

**Options:**
- `--format [text|json]`: Output format (default: `text`).

---

### `vcm session models`
Lists all models trained during a specific session with accuracy, timestamps, and position.

```bash
vcm session models SESSION_NAME
```

---

### `vcm session compare`
Compares two sessions side-by-side, summarizing net metric improvements, best models, and algorithmic recommendations.

```bash
vcm session compare SESSION_1 SESSION_2
```

---

### `vcm session explain-improvement`
Diagnoses why one model outperformed another within a session, attributing the change to code, dataset, or hyperparameter modifications.

```bash
vcm session explain-improvement SESSION_REF MODEL_1 MODEL_2
```

---

### `vcm session create-retrospective`
Reconstructs a session retrospectively from historical models trained within a given timeframe.

```bash
vcm session create-retrospective [OPTIONS]
```

**Options:**
- `--name TEXT`: Name for retrospective session.
- `--start TEXT`: ISO start timestamp.
- `--end TEXT`: ISO end timestamp.

---

### `vcm session export`
Exports session details, model comparisons, and charts to an interactive HTML report or structured JSON.

```bash
vcm session export [OPTIONS] SESSION_REF
```

**Options:**
- `--format [html|json]`: Target format.
- `--output TEXT`: File path to save report.

## Model Evolution Timeline Commands (`vcm timeline`)

Model evolution tracks sequential model iterations, detects performance regressions, surfaces progression gaps, and visualizes trajectories.

### `vcm timeline`
Displays the chronological evolution of models.

```bash
vcm timeline [OPTIONS]
```

**Options:**
- `--session TEXT`: Filter timeline to models within a specific session ID or name.
- `--since TEXT`: Include models trained since date (e.g. `2026-01-15`).
- `--until TEXT`: Include models trained until date.
- `--format [table|json|html|csv|ascii]`: Output visual format (default: `table`).
- `--output TEXT`: Destination file path for export.
- `--show-reasoning`: Display developer rationale alongside each model.
- `--show-changes`: Display code and hyperparameter deltas from previous model.
- `--highlight-best`: Visually highlight the best performing model in the timeline.
- `--accuracy-range TEXT`: Filter by accuracy range (e.g. `0.90-0.98`).

**Examples:**
```bash
# View timeline with reasoning in terminal table
vcm timeline --show-reasoning --highlight-best

# Export interactive HTML report with embedded SVG sparkline
vcm timeline --format html --output ./reports/timeline.html

# View ASCII line graph in console
vcm timeline --format ascii

# Export timeline to CSV for external analysis
vcm timeline --format csv --output ./reports/timeline.csv
```

---

### `vcm timeline analyze`
Analyzes the model progression trajectory to detect performance regressions and development gaps.

```bash
vcm timeline analyze [OPTIONS]
```

**Options:**
- `--session TEXT`: Analyze trajectory within a specific session ID or name.
- `--output TEXT`: File path to write analysis report.

**Example:**
```bash
vcm timeline analyze
vcm timeline analyze --output ./reports/analysis.txt
```

---

### `vcm timeline reason` / `vcm timeline-reason`
Adds or updates developer rationale for why a model version was created.

```bash
# Subcommand syntax
vcm timeline reason MODEL_ID ["NOTE"] [OPTIONS]

# Standalone command syntax
vcm timeline-reason MODEL_ID ["NOTE"] [OPTIONS]
```

**Options:**
- `--force`: Overwrite existing reasoning without error.
- `--show`: Display existing reasoning for the model.

**Examples:**
```bash
# Add or update reasoning
vcm timeline reason iris_v3 "Tuned max_depth to prevent overfitting" --force

# View reasoning
vcm timeline-reason iris_v3 --show
```

## Production & Operations Commands

### `vcm analysis`
Generates deep lineage and evolution analysis reports, or compares models.

```bash
vcm analysis [OPTIONS]
```

**Options:**
- `--report [full_lineage|summary]`: Type of lineage report to generate.
- `--compare MODEL1 MODEL2`: Compare two models by name.
- `--show-impact`: Show impact analysis flag.

**Examples:**
```bash
vcm analysis --report full_lineage
vcm analysis --compare iris_logistic_v1 iris_rf_v2
```

---

### `vcm reproduce`
Rebuilds and verifies a trained model from its Model DNA metadata. Checks out the exact Git commit, verifies dataset availability, re-executes training, and computes prediction parity.

```bash
vcm reproduce MODEL_REF
```

**Example:**
```bash
vcm reproduce iris_rf_v2
# Output:
# [INFO] Reproducing model 'iris_rf_v2'...
# [INFO] Checking out Git commit 7f8a9b2...
# [INFO] Verifying dataset data/iris.csv...
# [INFO] Executing training with hyperparameters: {'n_estimators': 100, 'max_depth': 5}
# [SUCCESS] Model reproduced successfully!
# Prediction Parity: 100.0% match
# Metric Delta: 0.0000 (Exact match)
```

---

### `vcm deploy`
Deploys a model to a target environment and appends an immutable deployment record to the audit trail.

```bash
vcm deploy [OPTIONS] MODEL_REF
```

**Options:**
- `--environment TEXT`: Target deployment environment (`staging`, `production`, `canary`). Default: `production`.

**Example:**
```bash
vcm deploy iris_rf_v2 --environment production
```

---

### `vcm audit`
Retrieves and validates the deployment audit trail for a target environment, showing active model binary, training author, commit SHA, and deployment timestamp.

```bash
vcm audit [OPTIONS]
```

**Options:**
- `--environment TEXT`: Environment to audit (default: `production`).

**Example:**
```bash
vcm audit --environment production
```

---

### `vcm config`
Views or updates VCM workspace configuration (`.vcmconfig.yaml`).

```bash
# View active configuration
vcm config show

# Update a configuration key
vcm config set KEY VALUE
```

---

### `vcm version`
Displays current VCM software version and system runtime details.

```bash
vcm version [--verbose]
```
